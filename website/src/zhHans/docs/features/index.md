# 功能特性

一个请求在 Pavonis 中依次经过的环节：

```text
客户端
  │
  ▼
按 host / path_prefix 选择站点 ── 无匹配 ──► 404
  │
  ▼
客户端认证（启用时） ───────────── 失败 ──► 401
  │
  ▼
请求频率限速 ───────────────────── 超限 ──► 429
  │
  ▼
请求头修改 → 出站连接（IP 池 / 请求代理） ──► 上游
（上传与下载的数据受流量限速约束）
```

## 站点模式（Site Modes）

Pavonis 的核心能力通过**站点模式**来体现。一个实例可以同时运行任意数量的站点，每个站点选择一种模式，覆盖容器镜像、代码托管、机器学习平台、包管理等主流场景。

→ [详细文档：站点模式](../sites/)

## 出站 IP 池

当你的服务器持有大段 IPv6 地址时（例如 HE Tunnel Broker 分配的 `/48` 子网），可以启用 IP 池，让 Pavonis 从池内随机或按规则选取出站 IP，有效规避上游平台对单一 IP 的速率限制。支持 `random`（随机）和 `ip_hash`（按客户端 IP 固定映射）等策略，也可以按站点单独覆盖。

→ [详细文档：出站 IP 池](./ip-pool)

## 流量与请求限速

按客户端限制带宽和每秒、每分钟、每小时的请求数，也可限制所有客户端合计的带宽，防止代理服务占用过多资源或被滥用。

→ [详细文档：流量与请求限速](./rate-limiting)

## 认证、请求头与请求代理

容器镜像站点和 `any_proxy` 站点支持客户端身份验证，用户文件支持热重载，更新用户列表无需重启。Pavonis 默认清理反向代理相关的请求头，避免将代理链信息泄漏给上游。上游请求还可以配置一个或多个请求代理，某个代理连不上时自动切换到下一个。

→ [详细文档：认证、请求头与请求代理](./auth-and-headers)
